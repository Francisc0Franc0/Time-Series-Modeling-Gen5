# Gen5 v0.1 Research Handoff Manifest And Gate Checklist

## Scope

This document defines the handoff contract from the Gen5 v0.1 Research Data Workbench to future research consumers. It covers adjusted daily market-data artifacts only.

It does not implement or authorize WFA folds, indicators, returns, labels, regimes, strategy signals, allocation, dashboard behavior, execution, live orders, provider expansion, or corporate-actions ingestion.

## Consumer Rule

Future WFA or research modules must consume a completed workbench handoff. They must not call Alpaca, inspect Alpaca response shapes, infer the latest market session, or reinterpret provider-specific cache state.

The authoritative inputs are:

- canonical adjusted daily bars generated by the workbench;
- the matching manifest row;
- severity-labeled health rows;
- audit, symbol coverage, and refresh-plan artifacts;
- the source-controlled universe registry used for symbol selection.

## Manifest Contract

Each workbench query handoff must include one manifest row linked to the generated artifacts. The current CSV manifest is written under ignored `runs/research_workbench/` and must preserve these fields before downstream research begins:

| Field | Required meaning |
| --- | --- |
| `wrapper` | Workbench wrapper that produced the handoff. |
| `as_of_timestamp` | Explicit timestamp used to resolve the latest completed session. |
| `latest_completed_session` | Data-layer-resolved latest complete daily session. |
| `resolution_reason` | Auditable reason for the session decision. |
| `requested_start_date` | Operator-requested research start date. |
| `requested_end_date` | Operator-requested research end date. |
| `fetch_start_date` | Provider/cache start date after data-layer bounding. |
| `fetch_end_date` | Provider/cache end date after clipping to completed sessions. |
| `universe_name` | Universe registry name used for symbol selection. |
| `universe_roles` | Registry roles selected for the query. |
| `requested_symbols` | Symbols requested from explicit input or registry filtering. |
| `returned_symbols` | Symbols with canonical bars in the handoff. |
| `cache_root` | Cache root used for the query. |
| `provider` | Must be `alpaca` for v0.1. |
| `feed` | Alpaca feed used by the request/cache path. |
| `refresh` | Whether the handoff attempted a credentialed cache refresh. |
| `git_sha` | Source revision when available. |
| `health_max_severity` | Highest severity emitted by the health report. |
| `bars_csv` | Path to canonical adjusted daily bars. |
| `audit_csv` | Path to the audit artifact. |
| `symbol_coverage_csv` | Path to per-symbol coverage. |
| `health_csv` | Path to severity-labeled data health rows. |
| `refresh_plan_csv` | Path to cache refresh planning evidence. |

If a credentialed refresh writes a merge summary, `merge_summary_csv` must point to the matching merge artifact.

## Bar Contract

Future consumers must treat the workbench bars as canonical only when the bar file satisfies the Gen5 adjusted daily schema:

- `symbol`
- `session_date`
- `open`
- `high`
- `low`
- `close`
- `volume`
- `adjusted`
- `timeframe`
- `provider`
- `as_of_timestamp`
- `latest_completed_session`
- `fetch_start_date`
- `fetch_end_date`
- `data_version_hash`

For v0.1 handoff use, `adjusted` must be `TRUE`, `timeframe` must be `1D`, and `provider` must be `alpaca`.

## Gate Checklist

Before the first future WFA consumer uses a workbench handoff, confirm:

- The handoff was produced by `scripts/query_research_data.R` or another documented workbench wrapper.
- `as_of_timestamp` is explicit and matches the bars, audit, and health artifacts.
- No handoff artifact includes rows after `latest_completed_session`.
- The requested universe name and roles are source-controlled in `config/universe_registry.csv`.
- `health_max_severity` is not `ERROR`.
- Any `WARN` rows are reviewed and accepted by the operator before research use.
- Duplicate symbol-session rows are absent.
- Missing, empty, partial, stale, and clipped-future conditions are visible in health or coverage artifacts.
- The manifest points to bars, health, audit, symbol coverage, and refresh plan artifacts from the same run.
- Generated cache and run artifacts remain ignored and are not committed.
- Future research code reads the handoff artifacts and does not call `g5_fetch_alpaca_daily_adjusted_bars()` or Alpaca HTTP APIs directly.

## Reserved Baselines

Future research should compare active decisions against cash/no-position and buy-and-hold baselines. In v0.1 these are contract concepts only. This checklist does not implement baseline returns, benchmark performance, strategy selection, or no-trade competition.

## Credential Boundary

Credentialed refresh and credential preflight remain operator actions. A handoff consumer must not require Alpaca credentials, load `.Renviron`, or perform network checks as part of default research validation.
